`docs/chaos-drill-20260728.md`가 07-28에 한 일을 **다시 돌 수 있게** 파일로 남긴 것이다.

## 왜 이 폴더가 생겼는가 (2026-08-26)

07-28 훈련은 결과를 잘 남겼지만 **방법을 안 남겼다.** 격리 스택을 띄우고 의존을 죽인
절차가 산문으로만 있어서, 4주 뒤 갱신하려니 "갱신"이 아니라 "처음부터"가 됐다.

복원 훈련은 반대다. `scripts/restore_drill.sh`가 있어서 08-10에 **낡은 훈련을 다시 도는
것**이 가능했다(`docs/restore-drill-20260810.md`). 그 차이가 이 폴더의 존재 이유다.

## 왜 블랙홀 서버가 필요한가

07-28은 `docker stop`으로 죽였다. 그건 **우리 컨테이너**에만 쓸 수 있다.
푸시와 토스는 목적지가 **코드 상수**라(`services/push.py`의 엔드포인트는 구독에 실려 오고,
`routers/payments.py:26`은 토스 도메인이 박혀 있다) 환경변수로 갈아끼울 수 없다.

그래서 `extra_hosts`로 DNS를 가로채 우리 가짜 서버로 보낸다. 가짜 서버는 TLS를 종단해야
하므로(대상이 전부 https) 사설 CA를 만들어 컨테이너 신뢰 저장소에 넣는다.

**'거부'와 '무응답'과 '5xx'는 다른 사고다.** 07-28이 Anthropic에서 배운 것이 그것이고
(연결 거부 0.5초 vs 무응답 115초), 새 의존에도 같은 구분이 필요하다.

## 쓰는 법

```bash
ops/chaos/up.sh                  # 격리 스택 기동(포트 18000·15432·11025)
ops/chaos/probe.sh               # 정상 기준선 — 주입 전에 반드시 먼저
ops/chaos/inject.sh push hang    # 주입: <대상> <모드>
ops/chaos/probe.sh               # 같은 프로브를 다시 — 차이가 결과다
ops/chaos/inject.sh none         # 원상 복구
ops/chaos/down.sh                # 정리
```

대상: `db` `smtp` `s3` `anthropic` `push` `toss` `openai` `gemini` `cohere`
모드: `refuse`(연결 거부) · `hang`(연결은 받고 무응답) · `error`(5xx) · `gone`(410)

⚠️ **개발 스택을 건드리지 않는다.** 프로젝트 이름이 `chaos`이고 포트가 전부 다르다.
훈련이 남의 작업 환경을 죽이면 안 된다(07-28의 규칙).
